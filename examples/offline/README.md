# 离线复现指南：不用 CFD，跑通"数据 → 模型 → 优化 → 推荐设计"

这个示例的目的是：在任何一台电脑上（不需要 ANSYS 或 CFturbo），用固定的随机种子把整条优化流程完整走一遍，
并确认得到的结果与参考值一致。它既可以用来检查环境装对没有，也可以用来验证代码改动没有破坏结果。

> **重要：** 示例中所有数据都是用公式编出来的合成数据，**不是 CFD 结果，也不代表任何真实设计的性能**。
> 真实数据以及 Windows 工程机上的采样和主动学习不在这个入口里运行。

## 运行方法

在仓库根目录执行。macOS / Linux：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-gui.txt
python -m impeller_app.reproduce --config examples/offline/config.json
python -m unittest discover -s tests -v
```

Windows（PowerShell）：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-gui.txt
python -m impeller_app.reproduce --config examples/offline/config.json
python -m unittest discover -s tests -v
```

如果 PowerShell 提示禁止运行脚本，可先执行 `Set-ExecutionPolicy -Scope Process RemoteSigned`（仅对当前窗口有效）。

建议使用 Python 3.13 或 3.14（最低支持 3.11）。

- 结果默认写入 `offline-output/`，该目录必须为空。再次运行请指定新目录，例如
  `--output-dir offline-output/repeat`。
- 配置文件和输出目录都相对于你运行命令的位置。
- 运行时会忽略 `IMPELLER_*` 环境变量，固定使用单个 CPU 线程、确定性算法和固定随机种子，
  并生成全新的设计变量配置、训练数据、固定测试集和模型，**不会读取作者的真实训练数据或历史模型**。
- 安装依赖的网络耗时不计入；运行本身应在 10 分钟内完成，通常十几秒内。
- 没有桌面环境的 Linux 上运行测试，请先设置 `QT_QPA_PLATFORM=offscreen`；Debian 精简镜像还需安装
  `libegl1 libgl1 libxkbcommon0 libdbus-1-3 libglib2.0-0 libfontconfig1`。
  如果测试因缺少依赖被跳过，要单独列出来，不能当作这项能力已通过验证。

## 示例做了什么

1. **生成 384 个合成样本。** 用固定种子在设计范围内均匀取点，按各变量的精度取整，
   再剔除不满足几何规则的点，直到凑够 384 行。`examples/offline/generate.py` 负责这一步；
   已提交的 `Compressor_Training_Data.csv` 是这份配置的快照，每次运行都会重新生成同样的数据。
2. **留出固定测试集。** 约 15% 的样本不参加训练，只用来检验模型。
3. **训练预测模型。** 预测效率、总压比和质量流量。
4. **用 NSGA-II 搜索。** 在模型上做多目标搜索，同时追求高效率和高总压比，得到预测的最优折中设计。
5. **在合成数据上查询真实前沿。** 把"公式给出的真值"当作观测数据，提取其中的最优折中集合，并按工程指标排序。
6. **挑出推荐设计。** 取工程排名第一的设计，写入 `pareto_selected_point.json`。

### 合成数据是怎么编的

把每个变量缩放到 0 到 1 之间（编号见下面的变量表），再用简单的线性关系得到各项结果：

| 结果 | 怎么算（z 表示该变量缩放后的值） |
|---|---|
| 效率 | 0.68 + 0.10·z0 − 0.025·L + 0.005·z12，其中 L 为 z1 到 z10 偏离 0.5 的平均平方偏差 |
| 静压比 | 1.05 + 0.20·z4 |
| 功率 | 80 + 25·z4 + 8·z11 |
| 质量流量 | 3.40 + 0.90·z5 + 0.30·z11 |
| 总压比 | 1.35 + 0.55·(1 − z0) + 0.15·z4 |
| 是否边界样本 | 质量流量小于 3.6 g/s 记为 1，否则为 0 |

## 变量与工况

范围包含两端；叶片数取 9、10、11、12 的整数；其余变量按"小数位"保留精度。
尺寸沿用仓库和 CFturbo 模板的单位，角度单位是度，程序在写入模板时会自动转换成弧度。
真实模板未随仓库提供，真实求解前需要自己核对尺寸单位。

| 序号 | 变量 | 范围 | 小数位 |
|---|---|---|---|
| 0 | d1s | 0.34–0.42 | 5 |
| 1 | dH | 0.044–0.056 | 5 |
| 2 | beta1hb | 70–84 | 3 |
| 3 | beta1sb | 20–35 | 3 |
| 4 | d2 | 0.45–0.53 | 5 |
| 5 | b2 | 0.044–0.056 | 5 |
| 6 | beta2hb | 40–54 | 3 |
| 7 | beta2sb | 40–55 | 3 |
| 8 | Lz | 0.185–0.215 | 5 |
| 9 | t | 0.0015–0.0035 | 6 |
| 10 | TipClear | 0.0007–0.0015 | 6 |
| 11 | nBl | 9–12，整数 | 0 |
| 12 | rake_te_s | −25 到 −15 | 3 |

出口静压 12 Pa 是固定工况，模型把它当作第 14 个输入，但它不是优化的变量。本示例的所有样本都恰好是 12 Pa，
查询真实数据时只接受与设定值相差不超过 0.25 Pa 的样本。

## 目标与限制

- **目标：** 同时让效率和总压比尽量高。
- **流量限制：** 质量流量不小于 3.6 g/s。
- **不作为目标：** 静压比只是记录量；模型也不预测功率。
- **搜索时的硬性限制：** 预测流量不小于 3.6 g/s，预测效率在 0.60 到 0.84 之间；
  求解可行概率不低于 0.65，几何安全概率不低于 0.55（本示例没有失败样本，两项默认为 1，不训练失败分类器）；
  d2 与 d1s 的差不小于 0.070；beta1hb 与 beta1sb 的差不超过 52 度；两个出口叶片角之差不超过 13.5 度；
  b2、t、TipClear、Lz、rake_te_s 都在各自范围内。
- **搜索时的软性扣分：** 预测不确定度大、rake_te_s 接近各叶片数对应下限（9、10、11、12 片分别为 −18、−19、−20、−21 度）、
  几何不够安全的设计会被扣分，使搜索偏向更稳妥的结果。这只是倾向，不是几何硬约束。

查询真实前沿时，先按工况带、几何规则、效率不低于 0.45、流量不低于 3.6 筛选，再取效率与总压比的最优折中集合。
**工程评分仅用于推荐，不能代替前沿本身。** 评分综合了效率余量、流量余量、前沿拐点位置、几何安全概率、
与其他成功样本的距离以及稳定性。

本示例生成的数值有时会因随机重采样而略有不同，导出的预测值只表示模型意见，不代表 CFD 验证过。

## 输出文件

| 文件 | 含义 |
|---|---|
| `Compressor_Training_Data.csv` | 13 个几何参数、出口静压和合成输出（全叶轮口径） |
| `fixed_test_set.csv` | 固定留出的 15% 测试集，不参与训练 |
| `nsga2_doe_model/` | 新训练的模型、两个归一化器，以及记录数据与模型指纹的清单 |
| `nsga2_surrogate_pareto.csv` | 模型预测的最优折中设计，含预测的效率、总压比、流量、不确定度和预测超体积 |
| `pareto_front_points.csv` | 在合成数据中提取出的真实最优折中集合 |
| `pareto_engineering_ranked.csv` | 上一张表按工程评分从高到低排序（排名从 1 开始） |
| `pareto_selected_point.json` | 工程排名第一的设计 |
| `summary.json` | 数据来源、软件版本、配置、推荐设计、误差、超体积、模型指纹和运行耗时 |
| `*.csv.meta.json` | 数据格式版本（第 2 版）与总压比的定义 |

几个容易混淆的列：

- **Efficiency**：等熵效率，无量纲；**PressureRatio**：静压比；**totalpressureratio**：静止系质量流量平均的总压比。
- **MassFlow**：全叶轮质量流量，单位 g/s，已按全叶轮口径给出，不要再乘叶片数。
- **Power**：功率（W）。真实流程按总焓升乘流量计算，本示例是公式值。
- **uncertainty_norm**：前两个输出的归一化不确定度均值，无量纲，不是带单位的置信区间。
- **surrogate_hv**：预测超体积，参考点取效率 0.6、总压比 1.0。整列取值相同，不是 CFD 超体积。
- **nearest_success_dist**：到其他合成样本的归一化距离，表示这个设计有多少数据支撑。
- **is_boundary**：流量低于 3.6 g/s 的保留样本标记，不代表几何失败。

## 参考结果与允许误差

参考环境：macOS arm64，Python 3.14.3，NumPy 2.4.2，Pandas 3.0.1，SciPy 1.17.1，scikit-learn 1.8.0，
PyTorch 2.11.0，pymoo 0.6.1.6。参数：种子 42，384 行，最多训练 240 轮，早停耐心 40，种群 48，进化 32 代。
主流程约 1.4 秒（首次导入和不同设备会更长）。

**检查 `summary.json` 里的下列数值：**

| 项目 | 参考值 | 允许的绝对误差 |
|---|---|---|
| 样本数 / 训练样本数 / 测试样本数 | 384 / 326 / 58 | 必须相同 |
| 真实前沿大小 | 50 | 必须相同 |
| 真实数据中的最高效率 | 0.7807738769 | 1e-8 |
| 真实数据中的最高总压比 | 2.01885 | 1e-8 |
| 推荐设计的工程评分 | 0.8300447961 | 1e-6 |
| 推荐设计的效率 | 0.7486677356 | 1e-8 |
| 推荐设计的总压比 | 1.6819375 | 1e-8 |
| 推荐设计的质量流量 | 4.49925 g/s | 1e-8 |
| 测试集效率误差（RMSE） | 0.00384668 | 0.001 |
| 测试集总压比误差（RMSE） | 0.02401822 | 0.01 |
| 测试集流量误差（RMSE） | 0.04061173 g/s | 0.02 |
| 预测超体积 | 0.15848537 | 0.03 |
| 预测前沿大小 | 30（参考环境） | 不同版本间在 1 到 48 之间即可 |
| 训练轮数 | 240（参考环境） | 1 到 240（可能提前停止） |

使用同样的软件版本连续运行两次，各 CSV 的数值应在 1e-7 内一致；跨平台或版本不同则用上表比较指标。
模型文件的指纹、绝对路径和耗时不要求跨机器相同。示例数据依赖 SciPy 的取样实现，
更换取样算法或大版本后需要重新建立参考值，`summary.json` 的环境一栏记录了实际版本，便于对照。

另一份在干净的 macOS Python 3.14.3 虚拟环境中的验证（NumPy 2.5.4、Pandas 3.0.6、SciPy 1.18.1、scikit-learn 1.9.1、
PyTorch 2.14.1、pymoo 0.6.2、PySide6 6.12.0）：96 个测试全部通过，没有跳过；默认复现约 11 秒，
预测前沿 31 行，超体积 0.15713864，仍满足上表允许范围。

## 自动测试与持续集成

`python -m unittest tests.test_reproduce -v` 会真正执行一遍训练和优化，并与入库的参考数据比对：
384 行合成数据、50 行真实前沿、推荐设计的三项输出、模型误差、超体积以及预测的极值。
预测的最高效率参考值为 0.775687（容许 ±0.01），最高总压比 2.040334（容许 ±0.05），
这些宽松容差用来容纳不同 CPU 或依赖版本带来的小差异；合成数据本身的结果仍按上表严格比对。
预测前沿的行数需要与摘要一致，并且在 1 到 48 之间：不同软件版本下，前沿上具体有哪些点会变，
所以通过极值和超体积来检查，而不要求恰好 30 行。

GitHub Actions 会在 Ubuntu（Python 3.11、3.12、3.13、3.14）和 Windows（Python 3.12）上运行测试与离线复现，
并在 Python 3.11 上做语法检查。

想确认测试"够灵敏"，可以临时把 `config.json` 里的 `seed` 从 42 改成 43，运行
`python -m unittest tests.test_reproduce.OfflineReproductionTests.test_documented_default_metrics -v`，
应当失败；改回 42 后应当通过。参考数据不会随运行自动更新。
