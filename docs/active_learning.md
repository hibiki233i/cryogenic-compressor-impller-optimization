# 主动学习说明

本文介绍模型怎样挑选下一批要用 CFD 验证的设计，每一轮留下哪些检验记录，以及失败的算例如何处理。
这是项目中最容易产生疑问的部分，建议配合 [优化问题说明](optimization_problem.md) 阅读。

## 基本思路

CFD 很贵，每算一个点都要花不少时间。主动学习就是让模型"自己提问"：每一轮从大量候选设计里，
挑出最值得花时间验证的那几个，算出真实结果后补充给模型，让模型在最关键的地方变得更准。

一轮的过程：

1. 用现有数据训练模型。
2. 用多目标遗传算法生成一大批候选设计。
3. 对每个候选，让模型"多次随机预测"，据此估计预测值和不确定程度。
4. 综合预测好坏、不确定程度、求解风险和几何风险，挑出本轮要验证的设计（模型可靠时通常 4 个）。
5. 用 CFD 计算这些设计，把结果和失败记录写入数据。
6. 评估模型这一轮的表现，进入下一轮。

## 每轮挑选几个、挑哪种

名额不是固定的，而是看模型当前**是否可靠**：

- **可靠的模型**：选三个"确实能明显改善前沿"的设计，外加一个"模型最拿不准的局部点"用来补盲区。
- **一般的模型**：减少对"改善前沿"的依赖，更多地探索未知区域。其中"改善前沿"的名额只有在预测误差、
  系统性偏差、概率判断准确度、不确定度估计合理程度这四项**全部**落在各自可用范围的较好一半时才给两个，
  任何一项偏弱就降为一个。
- **不可靠的模型**：只在已验证成功的设计附近做稳妥的空间填充，不冒险。

没有实际改善前沿价值的候选，不会为了凑够名额而被选中。

此外，主动学习会按大约 7:3 的比例交替选择"稳妥区域"和"流量边界附近"的设计。
最多 15% 的候选是在已成功的设计附近微调得到的，目标是流量刚好逼近 3.6 g/s 边界的设计，
且保持相同的叶片数和出口压力。

这些做法都是可调的经验性策略，**不能保证 CFD 一定成功**，其中估计流量的某些分位数也没有经过校准，
日志里会如实标注。叶片数的偏好不会越过求解风险、几何规则和流量这几道关。

## 每轮留下的检验记录

每轮结束，工作目录里会新增或追加下面这些文件，供复核时使用：

| 文件 | 内容 |
|---|---|
| `surrogate_validation_history.csv` | 每轮在固定测试集上的误差，以及交叉验证的平均值和波动 |
| `surrogate_cv_fold_history.csv` | 交叉验证中每一折的误差 |
| `fixed_test_predictions_history.csv` | 固定测试集上"CFD 实际值"与"模型预测值"的逐点对照 |
| `al_query_validation.csv` | 本轮每个被选中的设计：CFD 前的预测、不确定度、CFD 实际值、误差，以及落在一倍/两倍标准差内的情况 |
| `hv_history.csv` | 每轮的真实超体积、预测超体积、有效样本数、验证次数和模型指纹 |

补充说明：

- 交叉验证里，每一折自己再留出一小部分用来决定何时停止训练，归一化器只在真正用于训练的部分上计算，
  被检验的那一折只评估一次。
- 叶片数当作类别处理，数据划分尽量让各叶片数都有代表。训练时对过于密集的区域适度降低权重，
  避免主动学习反复在同一处采样而主导模型。
- 效率和压比的训练重点放在"流量合格且成功"的点上；流量预测使用所有成功的点。

### 记录方式的版本

新生成的记录会带上方法版本标记（例如 `acquisition_policy_version=3`、
`cv_protocol=outer_test_inner_early_stopping_v2`）。方法改过以后，**历史得分与现在的得分不能直接比较**。

## 失败的算例怎么处理

所有运行结果和失败原因保存在 `failure_records.csv`。核心原则：**区分"设计本身不行"与"工具出了问题"**。

| 情况 | 如何对待 |
|---|---|
| 软件、许可证、设置、CFX 前后处理出错 | 只记录备查，**不**当作设计不可行 |
| 明确的堵塞、无效流量、流场溢出 | 立即确认为"设计不可行"，用来训练可行性分类器 |
| CFturbo / TurboGrid 反复生成失败 | 重试后确认为"几何不安全"，用来训练几何分类器 |
| 求解器异常退出或发散，但没有明确的溢出迹象 | 只记录备查，不训练分类器 |
| 收敛但流量接近边界 | 保留在回归数据里，带"边界样本"标记，不与硬失败混在一起 |
| 数值上没有收敛到要求（见 [CFX 收敛](cfx_convergence.md)） | 不加入样本库，也不当作物理不可行 |

两个分类器都只用 12 个几何量学习，不使用出口静压和叶片数，以免"阶段差异"或"叶片数偏好"被误当成规律。
旧的 `failed_points.npy` 不再使用。失败表每轮重建，以前失败后来成功的点不会被永久列入黑名单。

## 做一个独立的主动学习实验（用于论文）

```powershell
python prepare_al_stage.py --name paper_clean_doe_s42 --seed-mode doe --seed 42
```

这条命令只复制数据、写配置、记录第 0 轮的真实超体积，**不会**启动几何、网格或 CFD，也不切换当前配置。
默认读取已保存的界面配置，也可以用 `--config <配置路径>` 指定。
新阶段位于原工作区的 `al_stages/<名称>/` 下，该目录必须事先不存在。

两种模式的实验含义不同：

| 模式 | 初始训练数据 | 含义 |
|---|---|---|
| `doe`（默认） | 清理后的 DOE 数据，不含固定测试集 | 从头开始，不引入历史主动学习的标签或模型 |
| `combined` | 当前有效的 DOE + 主动学习数据 | 在已有成果上继续追加，属于"热启动" |

实际运行时，在同一个终端会话里指定新配置再启动界面：

```powershell
$env:IMPELLER_APP_CONFIG = '<新阶段目录>\stage_config.json'
python -m impeller_app
```

然后在界面里明确点击启动主动学习（也可以在界面里直接载入该配置文件）。

要点：

- 每轮的随机性由"阶段种子 + 轮次"决定，可复现。`al_stage.json` 保存初始数据的指纹、配置、算法与软件版本、
  超体积参考点和实验类型。
- 恢复新阶段时会检查训练数据和固定测试集是否被换掉，防止同一条曲线悄悄用了不同的数据。
- 旧工作区若已做过数据清理却仍沿用旧阶段历史，主动学习会拒绝续跑并提示新建阶段。
- 论文用的超体积曲线（`hv_true_curve.csv/.png/.svg/.pdf`）只含真实 CFD 超体积：不平滑、不拼接旧阶段、
  不把预测提升当作实际提升。第 0 轮就是实际初始前沿。实际收益为零时曲线出现平台，也照实保留。
- 固定测试集是历史留出的数据，不是新采集的盲测样本。

## 不跑 CFD，只检查模型

```bash
python final_checkpoint_evaluation.py --output-dir _diagnostics/checkpoint_review
```

重新训练并评估一个模型，结果存在单独的目录，不会替换当前使用的模型，也不运行 CFD。
输出里，"训练样本数"只指真正用于更新模型的样本，"验证样本数"指单独留出用于决定何时停止的部分。

## 仅用初始数据的对照基准

界面的"仅 DOE 的 NSGA-II 基准"（命令行是 `--nsga2-only`）只用清理后的初始采样数据，
排除固定测试集，不读主动学习积累的样本，也不使用主动学习的失败标签。
它的模型单独保存在输出目录的 `nsga2_doe_model/` 中，不会覆盖主动学习的模型。
如需明确改为"初始 + 主动学习"数据，使用 `--nsga2-use-pool-checkpoint`。

## 任务结束时

- 正常完成或因前沿长期不再改善而停止时，界面会自动打开保存的 `hv_convergence.png`。
  无人值守运行时只保存文件。
- 运行时间到达上限而终止时，程序会记录并确认本次启动的子进程以及本次运行目录内新启动的 CFX 求解进程都已退出，
  清理脱离父进程的残留；不会按名称误杀其他工程正在运行的求解任务。
